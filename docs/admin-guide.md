# 管理员配置后台使用说明

版本1.5.0。浏览器打开 `http://127.0.0.1:8090/admin/`，账号见本机 `.local/admin-credentials.txt`。后台与数据API使用同一个Docker业务镜像，无额外前端服务。其他系统继续通过HTTP API获取数据。

## 一次完整配置

1. **数据表**：填写表标识、名称、保留天数（最多180天），新增字段并选类型，为每个字段填写中文说明（最多500字）。表结构及来源映射展示说明。业务日期必须是必填date；唯一键字段必须必填；要分组的字符串等字段标记为维度。金额使用decimal。注册后不可在页面直接改结构，改版时创建新标识，避免破坏已存历史数据。旧API未提供description仍兼容，旧字段无说明时明确显示“尚未填写说明”。
2. **接口接入**：选择目标表，填写完整接口地址、协议、GET/POST、日期参数、分页参数和响应列表路径。为每个目标字段填写源记录中的字段路径。源日期带时间时勾选需要转换的日期字段。填写鉴权信息并确认允许访问该主机，保存。HTTP请求头凭据只接受ASCII字符，参与供应商签名的App Secret允许合法Unicode。已有凭据不显示原值；留空保留，输入新值替换。一个表对应一个当前来源，可配置多张不同结构的表。
3. **连接测试**：选择一个已结束业务日，保存配置后测试。仅请求第一页并校验映射、字段类型，显示行数和字段；不会写入业务表，也不代表整天所有分页已通过。
4. **同步记录**：选择日期范围提交同步。服务逐日请求并完整翻页，全部记录通过后发布该日。失败日期保留上次成功版本，查看错误后重试。确认单日数据正确后再启用每天自动同步；时间使用北京时间，可设置每天回刷最近几天。
5. **加工与开放**：选择目标表，选择明细字段，或选择分组维度与聚合函数；可设置固定筛选、排序、外部允许传入的筛选字段及每页上限。用日期范围预览真实数据，保存并开放。接口地址为 `/api/v1/services/{接口标识}/query`。
6. **调用密钥**：为其他系统创建专用密钥，优先选择可调用接口及店铺/渠道/负责人数据范围，也可使用高级表授权；设置有效期和每分钟次数。完整密钥仅创建时显示一次，请立即保存到调用系统的服务端配置。停止合作时撤销密钥。

供应商批量接口也支持选择0或1起始页，必须以实际响应核对。本次商品日接口 `BDsDc38M0C` 的0和1都返回第一页，因此配置为1，后续请求2、3直到空页；不会静默去重。商品日表 `product_day` 使用必填 `product_day_id` 为业务唯一键，`dt`用于业务日期，`product_id`仍按文本保留前导零。

空库首次进入会显示空状态，不含演示数据。表需要成功同步或分批导入后，才能预览实际结果。默认完整日期校验开启：所选范围有未发布日期时返回409并列出缺失日期；管理员可在加工规则中明确关闭，此时响应会带不完整标记。

## 每日多次同步与按主键更新

“接口接入 → 配置 → 每日同步”支持添加、删除 **1～24 个北京时间**，精确到分钟，例如 `03:00`、`12:30`、`20:00`。时间不可为空或重复，保存后按时间升序显示。每个时间都会回刷“每次回刷天数”指定的昨日及以前数据；不读取今天。例如北京时间10月23日回刷1天就是10月22日；回刷7天是10月16日至22日，多个执行时间会重复更新这些日期。新增或保存时间不会自动开启同步，仍需勾选“开启每日同步”。

写入方式可选：

- **按主键更新**：同一业务日、同一业务主键整行覆盖；新键新增；此次未返回的旧键保留；NULL/可空字段缺失会覆盖旧值为NULL。空响应保留该日已有记录。保留期外的数据仍按180天等既有规则清理。
- **整日替换**：成功拉完后只保留本次返回的记录；空响应可发布空日。升级前配置保持此方式，避免静默改变其他来源。新增页面配置默认按主键更新。

写入方式在任务入队时确定；改变设置只影响后续新任务。手动同步也遵循该来源的写入方式。单次响应内或跨页出现重复主键仍会报错，不会静默去重。

每个时点、每个业务日独立记任务。同一业务日的前次任务未结束时，后续时点等待；服务恢复后补跑当天已到的时点，不补跑前几天错过的触发时间。每个时点只入队一次，失败不会每分钟无限重试，下一个已配置时点仍可再次同步。升级前当天已有单次定时任务按新配置的首个时点计，避免立即重复。

任务列表“本次接收”是这次接口返回数，“合并后”是该日最终可查询总数，后者包含保留的旧行。整次拉取和校验完成后才发布；失败或超限会保留旧数据。每个业务日合并后最多100万行，超过上限整体失败，不截断。

1.1.2使用数据库版本3。迁移保留旧单时点并转换为列表，账号、业务表和已发布记录保留。旧镜像不能直接对版本3运行；回退必须使用升级前备份恢复到新库后，连同旧镜像切换。实际操作前备份当前新状态，防止丢失升级后新增的数据。

## 数据处理范围

明细模式可选列、筛选、排序、分页；聚合模式可按一个或多个维度分组，支持sum、avg、min、max、count、count_distinct。sum/avg限integer/decimal，日期字段可直接分组。按日期范围汇总无需预先生成每一种起止日期组合。日期查询包含起止两天，最多180天且不能超出该表保留窗口或包含未来日期。

聚合直接使用已发布记录，decimal金额无损返回为十进制字符串；NULL保留。这里不自动推断经营指标口径，不把字段改名当作计算公式，也不执行任意SQL、跨表JOIN或自由脚本。可在“公式指标”中对数字汇总指标做四则运算；口径必须由配置者确认。

1.5.0新增“指定开放接口＋数据范围”密钥：可以限定只调用选定接口，并在汇总前按店铺/渠道/负责人强制过滤。原整表read密钥保持兼容，仍可查询该表全部字段和开放接口；受限的通用表read也覆盖授权行的全部字段，不能当成列权限。详见[调用密钥的数据范围与接口权限](key-permissions.md)。只向受信任的业务服务授予完整表权限。网页经营看板应经自己的后端调用，不能把机器密钥嵌入公开浏览器代码。

## 配置退款率、利润率与TOP榜

1. 在“聚合汇总”选择分组，例如渠道、店铺；不选则汇总整个查询周期。
2. 在“汇总指标”将选定退款金额求和命名为`refund_sum`，将支付金额求和命名为`paid_sum`。
3. 添加“公式指标”，返回列名`refund_rate`，公式`refund_sum / paid_sum`，保留小数位默认6。
4. 在“结果排序”选择`refund_rate`、降序；调用时`limit=5`就是前5名，排序在完整聚合结果上执行。
5. 如需排除小样本，在可选的“汇总后筛选”中配置`paid_sum > 1000`，再预览并保存。

公式支持加减乘除、括号和十进制常量，只引用数字汇总指标的返回列名。可同时添加多个独立公式，例如利润/净销售额、广告费/净销售额；不允许公式引用另一公式，必要时将表达式展开。先汇总分子分母再相除，不能用每日退款率简单平均替代周期退款率。

分母为0或缺失时返回空；比率`0.12`表示12%，需要百分数数值可显式乘100。公式先按所选小数位四舍五入，后筛选和排序；想区分很接近的比率时提高小数位（最多12）。按实际数据和确认口径选择退款字段，系统不自动选择“全部退款”还是“有效退款”。

## 对外调用

假设管理员创建并开放 `sales_by_shop`，定义按shop分组、amount求和。以下标识为说明示例，必须替换为真实已配置服务及凭据：

```http
POST /api/v1/services/sales_by_shop/query
Content-Type: application/json
X-API-Key: <调用系统密钥>

{"start_date":"2026-10-01","end_date":"2026-10-20","limit":100,"offset":0}
```

可传 `filters:[{"field":"shop","op":"eq","value":"某店铺"}]`，前提是管理员已允许shop筛选。调用者不能传fields/group_by/aggregates/formulas/result_filters/order_by/require_complete改变已保存规则。固定筛选与外部筛选按AND组合。分页默认不超过100及配置上限；传入超过上限返回422。

成功返回 `{code:200,data:{dataset,columns,rows,total,limit,offset,coverage,published_versions}}`。机器可先 `GET /api/v1/services` 获取自己有权访问的开放服务列表。原有 `/api/v1/datasets/{slug}/query` 和 `/api/v1/query/batch` 保留，支持直接按表查询及最多10个独立子查询。机器密钥到期或撤销后返回401，表权限不足403，服务未开放404。

## 凭据、配置与运行

来源凭据用Fernet认证加密后保存在数据库，接口不回显明文或密文。解密密钥 `DS_CONFIG_ENCRYPTION_KEY` 放在部署环境，不在数据库和镜像中。必须把数据库备份和该密钥分别安全保管；丢失密钥后需重新录入所有来源凭据。生成新密钥不等于轮换旧密文，本版不提供在线批量轮换。

页面保存的来源配置覆盖同名文件来源；在页面禁用来源也会遮蔽文件来源。文件来源仍兼容，但其凭据仍从环境读取；转为页面管理时需要重新提供加密凭据。修改页面配置后worker在下一轮读取，正在执行的任务使用开始时的配置完成；禁用阻止后续任务，不会强行中断已在执行的当天同步。手动同步与自动调度均只读取已配置来源，不接受外部调用方传任意URL。

每次编辑携带revision，配置已被另一页更新时返回409，重新加载后再编辑，避免静默覆盖。新建来源和加工规则不自动拉取或发布数据；来源必须启用且另行开启调度，才会自动请求外部。

## 升级、备份和回退

1. 备份旧库：`uv run python scripts/database-snapshot.py backup`；安全备份 `.env` 和配置目录。
2. 运行 `python scripts/configure.py`：保留账号/数据库密码，只在缺少配置加密密钥时生成。
3. 停止api和worker（保留数据卷），加载1.1.2镜像或构建后 `docker compose up -d --build --wait`。init在同一事务中增量添加多时间配置、任务写入方式与版本记录，原业务表及发布版本保留。
4. 验证 `/health/ready`、后台登录、worker心跳、原数据查询及来源连接测试。

1.1.0使用数据库版本2，1.0.0不能直接对新版库运行。回退前停止api/worker（保留卷），用备份脚本恢复到新命名 `ds_restore_...` 库，核对业务记录、账号与发布版本，切换旧镜像和连接配置；保留新版库及密钥供恢复。不要删卷或在原库上反向删表。实际本机验证记录见管理员后台交付报告；远程部署、真实源对账及人工发布审批不包含在本地测试结果中。

1.1.1仍使用数据库版本2，但字段定义新增description、来源允许1起始页；1.1.0程序不能直接读取这些新配置。升级须同时更新api和worker；回退须连同升级前数据库/元数据备份恢复，不能只换旧镜像。

## 空表键与说明修订（维护操作）

仅限没有任何存储记录、已发布日期或进行中批次的表。先备份数据库、配置和旧定义，停止api/worker，再执行：

```text
python scripts/revise-empty-dataset.py --expected <修订前定义.json> --revised <修订后定义.json>
```

命令核对完整旧定义，只允许更换业务唯一键、将新键设为必填及修改字段说明。类型、字段列表、名称、日期字段、维度、保留策略均不可借此变更；不放宽原有必填约束。检查、DDL及元数据在同一事务中提交，失败整体回滚，历史失败任务不删除。有数据时会明确拒绝，必须另行设计迁移方案。配置凭据照常从本地`.env`读取，可显式指定`--env-file`。

## 1.2.0升级与回退补充

1.2.0仍使用数据库版本3，无业务表迁移。新增公式保存在已有加工配置中。升级需同时更新api/worker。1.1.2不能识别新配置字段，因此已有新加工配置时不能仅切回旧镜像；应停服务并把升级前备份恢复到新的`ds_restore_...`库，验证后连同旧镜像切换，保留当前库及后续数据。不能用删字段或删真实加工规则来制造可回退。

## 1.3.0：点选汇总、公式与自然语言草稿

手工配置继续保留。在聚合模式的“批量添加求和指标”中勾选数值字段，一次生成多条求和指标，返回列名仍可修改。单独添加指标可继续选择计数、去重计数、平均、最大、最小等方式。

公式行可以选择已有的数值汇总结果，点按插入到公式当前光标；选项显示中文说明、聚合方式和返回列名。加减乘除及括号可直接点选。“比率快捷设置”选择分子、分母后填入公式。手工输入仍可使用，不会改变原有公式的计算精度及NULL规则。返回列名改变后须同步检查相关公式与排序。

“大模型配置”填写三项：API地址、模型名称、API KEY。地址支持OpenAI兼容的Chat Completions基础路径（如供应商给出的`/v1`地址）或完整`/chat/completions`地址。这里的模型名必须与供应商提供的一致，不是随意填写的名称。先“测试连接”，再保存并启用自然语言配置；测试按当前表单调用，不自动保存。连接测试也会调用供应商模型，可能产生少量费用。

KEY只写不读；空着保存表示保留旧KEY，勾选“清除已保存KEY”才删除。更换主机、协议或端口时，须重新填写KEY或明确清除，测试连接也遵守这一规则。允许无KEY的内网兼容服务。高级设置可以修改总超时（5～90秒）及`max_tokens`/`max_completion_tokens`参数名。Docker访问本电脑模型通常应填写`host.docker.internal`，容器内的`127.0.0.1`指容器自身。

在“加工与开放”选择表，然后用自然语言描述需求。例如：

> 按店铺、类目、渠道、负责人组合分组，调用方传入日期范围，汇总支付金额 paid_amount 和有效成功退款 valid_refund_amount；退款率等于退款汇总除以支付汇总，按退款率降序，允许调用方筛选店铺、渠道，每页最多100条。

流程为：**生成草稿 → 检查概览与口径 → 应用到手工表单 → 用日期范围预览 → 自己保存并决定是否开放**。四个维度一起选择表示按四字段的组合分组，不是自动生成四份独立报表。日期范围由外部调用方传入，不预存每一种日期区间。

生成过程只向所配置模型发送选中表的字段结构、中文说明和需求文本，不发送业务记录、来源地址、来源凭据或其他表内容。请不要在需求文字或字段说明中填写不希望发给模型的信息。模型结果只作为草稿，不能自动执行SQL、调用业务查询、保存配置或开放接口。

存在多个退款字段但只写“退款金额/退款率”时，会先列出候选，请补充准确字段名或中文口径。接口不存在的字段、跨表JOIN、同比环比、窗口函数及条件公式不在当前能力内；手工和自然语言都使用同一查询规则与后端校验。自然语言不会绕过校验，也不能替管理员确认财务口径。没有配置模型或模型失败时，手工配置照常可用。

生成期间更换表、修改需求或手工编辑时，旧响应不会应用到新内容。草稿应用不会自动开启接口，也不会改变正在编辑接口的固定标识；保存前仍可修改任一手工设置。


## 1.4.0 快速建表与映射

见[商品驾驶舱接入说明](cockpit-onboarding.md)。新建表支持从受限CREATE TABLE读取字段和中文说明，预览确认后应用，再创建；手工保留。接口接入默认同名映射，可勾选单个文本字段“换行/制表符转空格”；未选择的字段不转换。
