# Git 管理与首次导入

本次为开发后自检，L2 发布准备：将现有 1.6.0 独立数据服务纳入私有 Git 仓库。远程基线为 `2857f31e8e0229ecc9a74abb8b4f0c666c20ee2a`，原提交只有 README。本文不表示已经提交、推送或部署。

## 纳入范围与边界

- 纳入：服务源码及管理员后台、SQL 迁移、锁定依赖、Docker 配置、配置示例、测试代码、项目说明。
- 排除：真实 `.env`、`.local`、运行来源配置、密钥、数据库及备份、镜像和源码压缩包、验收截图和原始日志，以及用户提供的部署文档。
- `evidence/.gitkeep` 仅保留输出目录。历史报告中的证据路径指本机保存的历史材料，不代表仓库中附带证据或本次重跑通过。
- `config/product_day.dataset.json` 仅为旧表字段定义，保留以兼容现有测试；实际来源映射 `product_day.mapping.json` 不入库。
- `tests/key_description_independent/review_evidence.py`、`tests/independent/verify_delivery.py` 等历史交付交叉核验工具需要当时的本地材料，不能当作新克隆仓库的独立测试入口。
- 本轮不改 `data_service/`、SQL、接口、业务计算、权限、运行数据库、密钥或调度，也不操作经营看板。

## 首次取回代码

新环境运行 `python scripts/configure.py`，会创建缺失的空 `config/datasets.json`、`config/sources.json` 和本机配置。已有运行配置不覆盖。真实配置不进入 Git。

这是全新环境的初始化入口。迁移已有数据时，必须先按迁移方案安全恢复原配置加密密钥；不能用新生成的密钥解密旧库。不要在准备迁移时直接启动同步进程。

生成源码包使用 `python scripts/package-source.py`。脚本按白名单收集代码和示例，运行配置以空内容写入包中，排除历史证据和测试产物；目录缺失会自动创建。数据库备份和原加密密钥仍须独立迁移。

## 实施与测试追踪

| 编号 | 任务与预期 | 验证方式 |
| --- | --- | --- |
| GIT-01 | 保留远程初始历史；运行源码与原目录完全一致 | 对比远程基准及 `data_service/` 每个文件的 SHA256 |
| GIT-02 | 配置、凭据、数据、部署文档不进入候选 | 白名单、已知本机凭据内存匹配、Git 忽略规则和候选文件复核 |
| GIT-03 | 新克隆可生成空配置；重复初始化不覆盖已有配置 | 临时目录自动化测试，正常、缺文件、已有配置场景 |
| GIT-04 | 源码包在无 dist/evidence 时可生成，排除运行信息 | 临时目录打包、压缩包完整性及文件内容验证、泄露阻断用例 |
| GIT-05 | 本次准备没有引入语法或基础业务模型回归 | Python 编译、Ruff、无需数据库的 DDL/公式/调度测试 |
| GIT-06 | 独立复核候选文件、初始化和打包证据 | 由未参与实现的代理复核，结果单独记录 |

测试使用隔离临时目录和合成凭据，不连接运行数据库、第三方来源或云服务器。运行库恢复、Docker 实际构建与云端联调属于后续部署步骤，本轮不能判定通过。

## 后续维护

稳定版本在 main 管理，改动经测试和复核后提交；正式版本建立版本标识并对应镜像版本。Git 不保存运行数据，也不在每次推送时自动部署生产。数据库结构改变时，单独制定备份、迁移和回滚步骤。

本次候选在独立目录准备，原运行项目保持不变；未提交时可保留或放弃候选目录，无需回退运行服务。提交、推送、版本标记和云端切换各自记录真实结果，不把 Codex 自检等同于人工评审、CI 或发布批准。
