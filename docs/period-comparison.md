# 1.6.0 等长前周期比较与经营看板

数据服务仍是独立 Docker 项目，经营看板仍是独立本机演示项目。此版本保持数据库模式5，不修改商品记录、同步方式、数据范围或原有密钥授权。

## 对外接口

已保存的聚合查询接口支持在原请求中增加 `compare_previous_period: true`：

```json
{
  "start_date": "2026-10-20",
  "end_date": "2026-10-22",
  "filters": [],
  "limit": 5,
  "offset": 0,
  "compare_previous_period": true
}
```

当前周期包含首尾，共3天，前周期自动为10月17日至19日。10月22日单天的前周期为10月21日。两期使用相同的接口固定规则、传入筛选和密钥数据权限；不会为了环比扩大数据范围。

仅包含汇总指标、且不按日期字段分组的接口支持比较。每日趋势、纯维度字典和明细查询不要设置此参数。参数缺省或为false时返回结构和行为不变。字段只能为布尔值，字符串或数字不代替布尔值。

响应原有 `rows/columns/coverage/published_versions/total/limit/offset` 保留，另外附加 `comparison`：

```json
{
  "previous_period": {"start_date": "2026-10-17", "end_date": "2026-10-19"},
  "coverage": {"complete": true, "missing_dates": []},
  "published_versions": [],
  "status": "ok",
  "rows": [
    {
      "group": {"shop_name": "示例店铺"},
      "metrics": {
        "totalSalesAmount": {
          "current": "120.00", "previous": "100.00", "delta": "20.00",
          "relative_change": "0.200000", "status": "ok"
        }
      }
    }
  ]
}
```

上例只展示结构；实际 `group` 与接口分组字段一致，`published_versions` 为真实发布批次信息。数值聚合和公式返回列支持比较；非数值min/max列不计算环比。

比较跟随本期分页。假设某店铺本期进入TOP5、上期未进入TOP5，仍读取该店铺的上期完整汇总，不能拿上期排行榜第几行来凑配。跨渠道同名店铺按渠道＋店名分别匹配；空维度按真实NULL匹配。

本期和上期在同一只读快照内查询。费用比率先分别汇总各期金额并计算比率，再比较两个比率；不对单日比率简单求平均。金额计算使用Decimal，上期绝对值为相对变化分母，四舍五入到6位小数。

## 不可比状态

| 状态 | 含义与显示 |
| --- | --- |
| ok | 有效比较；delta为本期减上期，relative_change为delta÷abs(上期) |
| previous_zero | 上期为零；保留差额，relative_change为NULL；看板显示“上期为零” |
| current_missing | 本期聚合值为NULL，无法比较 |
| previous_missing | 上期无对应分组或值为NULL，无法比较 |
| incomplete | 本期或上期存在未发布日期，差额与相对变化为NULL |
| out_of_retention | 前周期超出保留窗口，不读取窗口外商品数据，比较结果为NULL |

源记录部分NULL时仍沿用SQL汇总有效值的既有口径，不补0。看板同时获取两期质量计数，提示比较基于已有值。发布日期完整不代表每个源字段都完整。

看板默认最近30天，历史从9月1日开始时，上一等长周期可能缺少8月日期，因此会显示前期数据不完整。选择历史齐全的周期可以正常比较；不得为了显示涨跌将缺日视作0。

## 看板口径与颜色

- 货品成本统一取 `net_goods_cost`，概览金额与费用占净销售额比例同时调整。底表的 `goods_cost` 原始字段保留。
- 金额和件数显示相对变化百分比；比率显示升降多少个百分点，提示中提供相对变化百分比。上期为零显示“上期为零”。
- 销售额、净销售额、利润、毛利、件数等上升标红；退款率、费用占比下降标红，反向标绿；持平和不可比为中性色。
- 绝对费用金额升降不能单独判断经营好坏，使用中性色。红绿还配合箭头/文字，不仅依赖颜色。
- 环形图角度按所列六项费用的相对金额分配360°；图例“占净销售额”使用净销售额分母，不要求六个标签相加为100%。中心显示服务端返回的所列费用合计。
- 出现缺失、负费用或合计不大于0时，不用绝对值伪造环形面积，显示可解释的费用列表或带符号图表。负费用参与实际汇总，不能擅自归0。
- 健康阈值、评分和诊断结论未确认，仍留空；周期比较不等于健康评级。

## 本机更新、迁移和回退

新安装环境使用1.6.0源码/镜像以及更新后的 `config/dashboard-services.example.json`。已有环境需把 `ds_dashboard_summary` 的 `goodsCost` 汇总和 `ds_dashboard_quality` 的 `goodsCostCount` 计数字段改为 `net_goods_cost`；summary增加 `listedCostTotal` 公式，表达式为六项费用别名之和。其余开放规则、筛选字段、最大条数与密钥权限不变。

2026-10-24用户确认本机更新后，API已更新至1.6.0，并通过管理员HTTP接口按revision更新上述两项规则；没有直接写业务数据库。更新前后同步空闲、工作进程心跳正常；20组真实查询、376项指标对账及5项独立真实页面验收通过。实际状态与回退凭据见本轮交付报告。安装工具遇到已有不同配置仍拒绝覆盖，不能拿初始化脚本强行覆盖管理员配置。

当前只读比较能力随数据服务API运行；worker的同步代码未变。更新API无需重启数据库或修改模式。操作前后核对同步任务与工作进程心跳；正在运行的同步禁止打断。

回退时使用保存的1.5.0 API镜像、恢复本次旧开放接口配置和看板源码即可；1.6.0没有模式迁移。恢复接口必须校验当前revision和规则没有其他人后续修改，不能盲目覆盖。保留原密钥，不重复签发或扩大权限。Docker包不包含经营看板、真实密钥或数据库数据。
