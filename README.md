# data_reservoir · 慕雅居独立数据服务

这是一个**单独部署的数据接入与查询项目**。包含独立的管理员配置后台，不包含经营看板、Vue、RuoYi菜单或原前端项目依赖。其他业务系统通过HTTP API取数。

```text
多个第三方HTTP接口 ──分页拉取──┐
                             ├→ 校验/字段映射 → PostgreSQL多数据集 → 范围/批量/聚合API → 其他系统
其他系统 ──分批推送API─────────┘
```

每个数据集可自行定义字段类型、中文说明、日期字段、业务唯一键、维度和保留天数；不是固定写死的一张商品表。默认保留180天。来源支持“按主键更新”和“整日替换”两种方式：按主键更新时，相同键整行覆盖、新键新增、未返回旧键保留；全部校验成功后原子发布，失败保留旧版本。分批推送API保持原有整日替换行为。跨表批量查询支持独立子查询，不做跨表JOIN或任意SQL执行。

本仓库管理程序代码和脱敏配置示例，不附带运行数据库、真实凭据、镜像包或历史验收产物。首次导入边界、离线验证和后续版本管理见 [Git 管理说明](docs/repository-management.md)。

## 独立Docker启动

在本目录执行。需要Docker Engine/Compose；生成随机本地配置的辅助脚本只需Python3标准库，也可手工从`.env.example`创建`.env`并填写随机密码及连接地址。

```powershell
python scripts/configure.py
docker compose up -d --build --wait
```

- 管理员配置后台：http://127.0.0.1:8090/admin/
- 服务入口：http://127.0.0.1:8090
- 离线可读接口目录：http://127.0.0.1:8090/docs
- OpenAPI：http://127.0.0.1:8090/openapi.json ，可导入Apifox/Postman。
- 本机管理员账号保存在`.local/admin-credentials.txt`，不在镜像内。
- 数据库用独立卷`muyaju-data-service_data-service-db`；不读取原看板数据库。
- `config/datasets.json`、`config/sources.json`默认空，调度默认关闭；不会调用真实第三方接口或填入演示数据。

首次初始化只创建管理员与基础表，再注册数据集配置；再次运行不改管理员密码，不覆盖已有字段定义。有历史数据时，字段结构变更须另行迁移或新建数据集。1.1.1提供显式空表维护命令，仅允许无记录、无发布数据、无进行中任务的表修订唯一键和说明，使用前必须备份并停止写入，见管理员说明。

## 使用顺序

1. 登录管理员配置后台，在“数据表”定义字段及每行中文说明、业务日期、唯一键和维度。
2. 在“接口接入”选择目标表，填写HTTP来源、字段映射及凭据，保存并测试。
3. 在“同步记录”选择日期范围同步，或在接入配置中设置一个或多个北京时间并启用每日同步；也可由外部系统通过分批导入API推送。
4. 在“加工与开放”选择字段、维度、聚合、公式、汇总后筛选和排序；支持批量求和、点选公式。也可先在“大模型配置”填入地址、模型名和KEY，再用自然语言生成可审核草稿。预览后保存并开放查询服务。
5. 在“调用密钥”为店长或其他系统选择开放接口及店铺/渠道数据范围；高级整表read/write继续保留。通过生成的接口地址调用。

完整操作见[管理员配置使用说明](docs/admin-guide.md)。命令和配置文件方式仍兼容。
调用方不需要知道数据库地址，也不应拿管理员密码。API密钥是系统间凭据，放在其他系统的服务器配置，不嵌入公开浏览器代码。

## 停止与验证

```powershell
docker compose stop
```

该操作保留数据卷。不要将`docker compose down -v`作为停止方式，它会删除数据。

开发依赖使用Python3.12和uv；`uv sync --frozen`安装。测试仅运行在可识别的专用`*_test`数据库，不能填写应用库。完整执行方法和证据在交付报告中。


## 1.4.0：从建表语句接入商品驾驶舱

数据表 → 新建数据表 → 从建表语句快速导入：粘贴 CREATE TABLE，解析后检查中文说明和类型，明确选择业务日期与唯一键，应用到表单后再创建。来源配置默认同名字段映射，可手工调整。解析不执行原始 SQL，不自动发布开放查询接口。

本次新来源为商品驾驶舱日表 `ads_product_dashboard_daily`，接口ID `B08GhuIzQB`，使用 `daily_id` 单字段唯一键、`dt` 业务日期，保留180天。原 `product_day` 保留。详细字段取舍、同步覆盖和回滚见 [接入说明](docs/cockpit-onboarding.md)；历史验收证据仅保存在本机。


## 1.5.0：同一接口按密钥隔离店铺数据

[配置说明与调用示例](docs/key-permissions.md)：密钥分别选择开放接口和行范围，按渠道、店铺、负责人组合条件；先过滤权限再聚合、计算公式与排序。旧密钥协议保持兼容。模式版本5仅新增api_keys.policy，不修改商品记录或同步引擎。升级前须等待同步空闲、备份并验证恢复；历史测试和本地交付原始证据仅保存在本机。


## 1.6.0：可选等长前周期比较

开放聚合查询可传`compare_previous_period: true`，在同一授权和只读快照内按本期分组匹配上一等长周期。默认关闭，不改变已有请求；上期为零、NULL、缺日和超保留窗口均明确标识。数据库模式仍为5。经营看板的货品成本改取`net_goods_cost`；数据服务Docker仍不包含看板。接口契约、环比口径及回退见[周期比较说明](docs/period-comparison.md)。
